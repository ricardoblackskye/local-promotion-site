# Plan — Add the missing ESLint configuration (#17)

**Issue:** [local-promotion-site#17](https://github.com/ricardoblackskye/local-promotion-site/issues/17)
**Branch:** `plan/17-eslint-config` · **Status:** awaiting GATE 1

## Goal

Make the repo's declared lint **satisfiable**, so the Dark Factory — and any CI — judges this repo by the
code it wrote rather than by a missing file. Repo-agnostic in shape: *a `lint` script must resolve a
config that references only declared packages.*

## Root cause (verified, not inferred)

`package.json` declares:

    "lint": "eslint . --ext ts,tsx --report-unused-disable-directives --max-warnings 0"

and the repo contains **no ESLint configuration at all**. Confirmed three ways:

- the GitHub contents API's root listing for `main` — no `.eslintrc*`, no `eslint.config.*`
- `git log --all --diff-filter=D --name-only` — nothing eslint-named was ever deleted
- `.gitignore` — nothing eslint-named is ignored

So the gate's command exists and **nothing can satisfy it, on any machine**. The Dark Factory run against
#15 halted after three iterations on `ESLint couldn't find a configuration file`, then tripped its breaker.

## The fix — verified by probe, not proposed

A legacy `.eslintrc.cjs` using **only packages the manifest already declares** (`eslint ^8.57.0`,
`@typescript-eslint/{parser,eslint-plugin} ^7.2.0`, `eslint-plugin-react-hooks ^4.6.0`,
`eslint-plugin-react-refresh ^0.4.6`) was run against the tree. It reduces the whole repo to **two findings**:

| file                                      | finding                                           | severity                |
|-------------------------------------------|---------------------------------------------------|-------------------------|
| `src/test/lib/ricosRenderer.test.tsx:331` | Unused eslint-disable directive (`no-script-url`) | **error**, `--fix`-able |
| `__mocks__/framer-motion.tsx:49`          | `react-refresh/only-export-components`            | warning                 |

Legacy `.eslintrc.cjs` is chosen over a flat `eslint.config.js` because it fits the `eslint` 8.57 the
manifest pins and **adds no dependency**. A flat config importing `typescript-eslint` was the Dark
Factory agent's guess and fails `ERR_MODULE_NOT_FOUND` — that package is not declared.

## Tasks (RED/GREEN on the repo's own command)

- **RED:** `npm run lint` exits non-zero from a clean checkout (`ESLint couldn't find a configuration
  file`). This is the failing state, and it is already reproduced.
- **GREEN, step 1:** add `.eslintrc.cjs` — config only, no source edits.
- **GREEN, step 2:** clear the unused directive at `ricosRenderer.test.tsx:331` via `--fix` (mechanical).
- **GREEN, step 3:** resolve the `react-refresh` warning in `__mocks__` — see the open question below.
- Commit the config and the source fixes **separately**, so the config's effect is visible on its own.

## Acceptance

1. `npm run lint` **exits 0** from the repo root on a clean checkout.
2. The config references **no package absent from `package.json`**.
3. Provable on the laptop — the declared command, run by hand, is the evidence.
4. No new dependency added.

## Risks / open questions

- **How to handle `__mocks__/framer-motion.tsx`.** Ignoring `__mocks__` is honest (it is test fixture
  code, not shipped UI) and keeps the rule strict where it matters. The alternative — relaxing
  `only-export-components` — weakens a fast-refresh guard to satisfy a mock, which I would not choose.
- **Does MegaLinter run its own ESLint?** The repo carries `.mega-linter.yml`; if MegaLinter's ESLint
  linter is active it will now use this config. Worth confirming the CI job stays green rather than
  assuming it.
- **`.eslintrc.cjs`, not `.js`** — the package is ESM (`"type": "module"`), so a `.js` config would be
  parsed as a module and fail.

## Why it matters beyond this repo

Until the lint can pass, **every** Dark Factory run against this repo is rejected for a reason unrelated
to the code it wrote. That is the `harness` row of agent-eve#743, and the factory half is agent-eve#742
(the gate now runs from the checkout root — merged into this work's prerequisite).
