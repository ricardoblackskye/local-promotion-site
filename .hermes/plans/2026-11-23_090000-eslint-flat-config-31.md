# Plan - one ESLint config that BOTH majors load (#31)

**Issue:** [local-promotion-site#31](https://github.com/ricardoblackskye/local-promotion-site/issues/31)
**Parent:** #20 (via #30)
**Branch:** `fix/31-eslint-flat-config`

## Goal

MegaLinter's ESLint (v10.8) and the repo's (v8.57) must read **the same config**, so `npm run lint` and
`JAVASCRIPT_ES` agree with each other. The goal is not "make MegaLinter green" - it is "make the two agree",
because a config that only one of them can read means the repo's gate and the CI gate are checking
different things. That is the actual defect.

## The situation

| | version |
| --- | --- |
| repo `eslint` | `^8.57.0` |
| repo `@typescript-eslint/eslint-plugin` / `parser` | **`^8.73.0`** |
| repo `eslint-plugin-react-hooks` | `^4.6.0` (pre-flat) |
| repo `eslint-plugin-react-refresh` | `^0.4.6` (pre-flat) |
| repo config | `.eslintrc.cjs` (legacy, added by #17) |
| repo gate | `eslint . --ext ts,tsx --report-unused-disable-directives --max-warnings 0` |
| MegaLinter | `eslint v10.8.0`, which dropped `.eslintrc.*` |

## Step 0 - the fact that reshapes this

`@typescript-eslint` is at **v8.73.0**, not v7. v8 is where the flat-config exports arrived
(`configs.flat`, `tseslint.config()`), so the plugin set is not the obstacle. What remains:

1. `--ext ts,tsx` is a legacy flag **removed in ESLint 9+**; a flat config selects by `files:` globs instead.
2. `react-hooks@4.6` and `react-refresh@0.4` are pre-flat plugins - usable in a flat config, wired by hand.

## Step 1 - feasibility, BEFORE any repo change

With a scratch config and no commits, establish:

- does one `eslint.config.js` load under the repo's own 8.57?
- does the **same file** load under ESLint 10.8 (MegaLinter's)?
- does `@typescript-eslint` 8.73's flat export work under ESLint 10?

**If a single config cannot serve both, STOP and report.** Do not force it, and do not disable the descriptor
to get a green - that would be disarming the check, which #30 and #20 both rule out.

## Step 2 - the config (only if Step 1 passes)

`eslint.config.js`: the `tseslint` flat base, `react-hooks` and `react-refresh` wired by hand, and
`__mocks__` ignored - matching #17's deliberate decision, so this does not silently change what is checked.

## Step 3 - the script

Replace the `--ext` form with the flat-config equivalent, keeping `--max-warnings 0`.
The repo's gate must stay as strict as it is now.

## Step 4 - the control

As #17 did: deliberately break something and prove the config **catches** it.
A config that *loads* is not a config that **works**.

## Acceptance

- `npm run lint` exits 0
- MegaLinter's `JAVASCRIPT_ES` / `TSX` / `TYPESCRIPT_ES` stop reporting the migration error
- the deliberate-broken control fires
- **no descriptor disabled**, and no rule silently dropped in the move to flat config

## Risks

- The flat-config move can quietly lose rules that the legacy `extends` brought in. The control (Step 4) is the
  guard, and comparing the rule sets before/after is worth doing explicitly.
- This touches the gate #17 just made honest, so it needs **both** gates green, not one.
