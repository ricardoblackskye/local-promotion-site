# Blog Proxy Production ESM Fix Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Restore live Wix Blog posts in Preview and Production by fixing the shared-module import used by the Vercel Blog proxy functions.

**Architecture:** Keep the existing same-origin proxy architecture: the browser calls `/api/blog` and `/api/blog-post`, while Vercel calls Wix server-side. The fix will make the shared TypeScript module resolvable by Vercel's native Node ESM runtime without changing the API contracts or frontend behavior.

**Tech Stack:** Vercel Node.js Serverless Functions, TypeScript, Vite, Vitest, Wix SDK, GitHub Actions.

## Verified investigation findings

- Backlog issue: [#9 — Bug - Blog details are broken in Preview and Prod](https://github.com/ricardoblackskye/local-promotion-site/issues/9).
- The latest release is merge commit `14c7ef3`, which merged PR #7 into `main`.
- The current Production deployment is READY, but both endpoints fail at runtime:
  - `https://black-skye.vercel.app/api/blog`
  - `https://black-skye.vercel.app/api/blog-post?slug=the-common-pitfalls-leading-to-ai-strategy-failures`
- Direct endpoint probes return `FUNCTION_INVOCATION_FAILED`.
- Vercel logs identify the exact failure:

  ```text
  Error [ERR_MODULE_NOT_FOUND]: Cannot find module '/var/task/api/blog-shared'
  imported from /var/task/api/blog.js
  ```

- The released handlers import the shared module using extension-free relative imports:

  ```ts
  from './blog-shared'
  ```

- The local TypeScript/Vite toolchain resolves this import, but the deployed native Node ESM loader does not resolve the emitted extension-free import to `blog-shared.js`.
- The frontend correctly falls back to mock posts when `/api/blog` fails; the mock tiles are therefore a downstream symptom, not a Wix data/filter problem.
- No source changes have been made on this issue branch yet. The branch is `fix/blog-proxy-esm-9`, created from the released `main`.

## Root cause

The Vercel function bundle contains `api/blog.js` and `api/blog-post.js`, but their extension-free imports point to `/var/task/api/blog-shared`, which Node's ESM loader cannot resolve. Module loading fails before either handler can validate configuration or call Wix. Both Blog proxy endpoints consequently return `FUNCTION_INVOCATION_FAILED`.

## Intended fix

Use an ESM-compatible import specifier for the shared local module in both Vercel handlers, while preserving TypeScript compilation and Vercel deployment behavior. The implementation should validate the correct extension convention with a deployed Preview rather than assuming that a local build proves runtime resolution.

The preferred implementation candidate is to change both imports to the emitted JavaScript extension:

```ts
from './blog-shared.js'
```

If the repository's TypeScript configuration or Vercel bundler rejects that specifier, the implementer must use the smallest alternative that produces a resolvable deployed import and document the evidence. Do not reintroduce duplicated helpers or abandon the server-side proxy.
