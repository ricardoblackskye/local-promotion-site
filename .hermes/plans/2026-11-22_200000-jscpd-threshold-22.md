# Plan - Make the duplication check meaningful (#22)

**Issue:** [local-promotion-site#22](https://github.com/ricardoblackskye/local-promotion-site/issues/22)
**Branch:** `plan/22-jscpd-threshold` · **Status:** awaiting GATE 1

## Goal

The `COPYPASTE_JSCPD` check must be **red on genuine drift and green on a healthy codebase**. Today it is
red regardless of the change under review, which makes it noise. Stated so it holds for any repo: *a linter's config
must express the rule's intent, not the linter's most aggressive default.*

## Root cause (measured, not inferred)

There is **no `.jscpd.json`** in the repo (confirmed: the raw URL 404s), so MegaLinter's default applies -
and that default fails on *any* duplication at all:

```
jscpd found too many duplicates (3.2%) over threshold (0.0%)
```

Measured against the tree at `main`, with `--min-tokens 50`:

| scope                              | clones | duplicated lines | duplicated tokens |
|------------------------------------|--------|------------------|-------------------|
| everything (as MegaLinter runs it) | **32** | 280 (4.06%)      | 1934 (4.42%)      |
| test directories excluded          | **2**  | 19 (0.56%)       | 144 (0.69%)       |

**About 93% of the findings are test setup repetition** - the same scaffolding repeated per spec. That is
not the duplication this rule exists to catch.

## The fix

Add `.jscpd.json`:

- **scope jscpd away from the test directories** (`src/test/**`, `tests/**`, `__mocks__/**`) - test setup
  repetition is normal and often correct
- **set a threshold the production code meets with headroom** - the measured figure is **0.56%**, so **1%**
  leaves room to grow while still failing on real drift

The 2 production clones (including `CaseStudies.tsx` <-> `Services.tsx`) stay under the threshold. Refactoring
them is a separate decision from making the check honest.

## Tasks

- **RED:** `npx jscpd` against the tree fails today - 32 clones, 4.06% against a 0% threshold. Already
  measured.
- **GREEN, step 1:** add `.jscpd.json`; re-run locally and confirm it passes.
- **GREEN, step 2:** **control** - the threshold must still fail on genuine duplication in shipped code.
  Prove it by temporarily lowering the threshold below the measured 0.56% and confirming it trips, or by
  running jscpd against a synthetic duplicate. **A threshold that cannot fail is the bug being fixed.**
- **GREEN, step 3:** push and confirm the MegaLinter job reports jscpd as passing.

## Files

- `.jscpd.json` (new)

## Acceptance

1. jscpd passes on `main` with the config in place.
2. **A genuine clone in shipped code still fails** - proven by the control above, not asserted.
3. **Provable locally**: `npx jscpd` with the config is the evidence.
4. No other linter is disabled or weakened to make this pass.

## Risks / open questions

- **1% is close to the measured 0.56%.** A large feature could legitimately trip it. That is arguably the
  point - but if it proves noisy, the honest response is to refactor or raise the number deliberately, not
  to disable the linter. Note the measured baseline in the config as a comment-adjacent record.
- **Test duplication is real, just not this rule's business.** If the repeated scaffolding is worth
  removing, that is its own issue with its own value - not something this threshold should force.

## Why it matters beyond this repo

This is one of six gates that were red today for six different reasons (agent-eve#743). A check that cannot
vary with the change under review carries no signal, and it blocks every PR - which is exactly what
happened here.
