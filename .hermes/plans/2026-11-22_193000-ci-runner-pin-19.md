# Plan — Make the CI gates runnable on their runner (#19)

**Issue:** [local-promotion-site#19](https://github.com/ricardoblackskye/local-promotion-site/issues/19)
**Branch:** `plan/19-ci-runner-pin` · **Status:** awaiting GATE 1

## Goal

A CI check that fails for an infrastructure reason is worse than no check: it reports red for work that may
be fine, and it blocks every PR. Restated repo-agnostically - *a workflow must not depend on an unpinned
runner image it cannot run its tooling on.*

## Root cause (verified)

| evidence                            | value                                                                |
|-------------------------------------|----------------------------------------------------------------------|
| `.github/workflows/ci.yml` L15, L39 | `runs-on: ubuntu-latest` -> now resolves to **ubuntu 26.04**         |
| `package.json`                      | `@playwright/test`: **`^1.42.1`** (early 2024)                       |
| run 45054273711                     | `test`: **success**; `e2e`: failure at *Install Playwright browsers* |
| the log                             | `ERROR: Playwright does not support chromium on ubuntu26.04-x64`     |

**The unit tests pass.** The e2e job dies before a single test runs, on every branch including `main`.

## The fix - Route A, pin the runner

    runs-on: ubuntu-24.04

Applied to **both** jobs in `ci.yml`. Pinning only the e2e job fixes today's red; pinning both stops the
unit job drifting onto 26.04 later and repeating this in a week.

Chosen over bumping `@playwright/test` because it is one line, reversible, and adds no dependency.
**Route B is not rejected, only deferred** - see below.

## Tasks

A workflow change, so the RED/GREEN anchors are CI runs rather than unit tests (a runner image cannot be
reproduced locally):

- **RED:** run 45054273711 - the e2e job fails at *Install Playwright browsers*. Already observed.
- **GREEN, step 1:** add the pin to both jobs; push.
- **GREEN, step 2:** confirm the e2e job reaches *Run e2e tests*, and read what it reports.

## Files

- `.github/workflows/ci.yml` (two lines)

## Acceptance

1. `CI - Tests` is green on `main`, **or** the e2e job reaches the tests and fails only for real reasons.
2. The browser install completes on whatever image the job uses.
3. Evidence is the CI run plus a job log showing *Run e2e tests* executing.

## Risks / open questions

- **The e2e tests may then fail for real.** They have not executed in CI since the runner image moved, so
  nobody knows whether they pass. If they fail, that is a **separate** issue about the specs - not a reason
  to re-pin or to weaken the job.
- **A dated pin expires.** GitHub retires runner images; `ubuntu-24.04` is supported today and will not be
  forever. Record the reason in a comment beside the pin so it is not read as arbitrary.
- **Route B remains owed.** Bumping `@playwright/test` to a 26.04-capable version is the real fix; the pin
  is a stay of execution. It belongs in a dependency pass, where the browser downloads and any spec fallout
  are handled together.

## Why it matters

Every PR in this repo is blocked while branch protection requires this check - including #18 (the ESLint
config), which is correct and green apart from it. The Factory's own runs are gated by these checks too, so
a permanently-red e2e is a permanently-blocked factory on this repo.
