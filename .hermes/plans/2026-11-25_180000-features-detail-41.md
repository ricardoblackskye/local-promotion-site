# #41 — SkyeForge Features: cards open a detail page

Plan for `ricardoblackskye/local-promotion-site#41`. Gate 1 pending: no implementation code until this
is approved.

## Goal

Clicking a card in the Services & Expertise collection opens a detail page about that entry. The
section is renamed **SkyeForge Features**, and the route is `/features`.

The collection is Wix's `Services`. `title` and `description` are already fetched; the **missing
fields are `Details` and `Image`**.

## The one ambiguity, and how I will resolve it

The issue says *"The path should be /features"* and also asks for a **detail page** per card. A single
path cannot be both, so I read it as:

| route | what it is |
| --- | --- |
| `/features` | the renamed collection page (today the home-page section) |
| `/features/:slug` | the detail page for one entry, keyed on the `slug` already fetched |

That mirrors `/blog/:slug`, which this repo already does. **If you meant `/features/<something else>`
— an id, or a different shape — say so and the plan changes in one line rather than in the code.**

## Tasks (TDD: RED then GREEN, separate commits)

| Task | The RED asserts | The GREEN does |
| --- | --- | --- |
| 1 | the hook requests and maps `Details` and `Image`, and a record missing them still yields a usable entry | extend `WixService`/`mapService` and the query's fields; extend the `Service` type |
| 2 | a detail page renders title, description, the rich `Details`, and the image for a given slug | the page component, reusing `ricosRenderer` for `Details` |
| 3 | `/features/:slug` resolves to that page and an unknown slug does not crash | the route in `App.tsx` |
| 4 | each card is a link to its own detail route | the card becomes a `<Link>`, keeping its current markup otherwise |
| 5 | the section heading reads **SkyeForge Features** and the section id/path is `/features` | the rename, in one place (`constants.ts` and the section) |
| 6 | a record with **no** `Details`/`Image` degrades gracefully | the fallbacks |

Task 1 and task 2 carry controls: missing fields must not break the page, and an unknown slug must
not crash the route.

## Risks, and what I do about them

| Risk | Handling |
| --- | --- |
| The Wix **field keys** for `Details`/`Image` are not literally `details`/`image` | verify against the live collection before wiring the mapping, and tolerate both if needed — a guess here fails at runtime, not at build |
| `Details` is Wix **rich content** rather than plain text | reuse the existing `ricosRenderer` instead of inventing a renderer |
| The repo **prerenders/SSRs** a fixed route list | a new route must be added to that path too, or the built site 404s where the dev server works — the build output is the check |
| Renaming the section breaks something that matches on the old text | grep for the old string across `src` before changing it |
